Run JavaScript/TypeScript in a confined runtime to compose tool calls and filter intermediate data before returning a concise result.

Use execute to inspect several files or endpoints, chain calls whose inputs come from earlier results, or summarize large outputs in one turn. Return when the next step needs your judgment. Use the exact namespaced paths and argument shapes shown by the catalog or search({ query: "..." }); special names use bracket notation.

Discover the file tools with `return search({ query: "glob read", namespace: "$opencode", limit: 2 })`. When these tools are available, their signatures support this eight-file bounded line-count check:
```js
const { files, ...listing } = await tools.$opencode.glob({ pattern: "src/**/*.ts" });
const pages = await Promise.all(files.slice(0, 8).map(({ path }) => tools.$opencode.read({ filePath: path, limit: 1 })));
return { ...listing, inspected: pages.length, files: pages.filter(page => page.type === "text-page" && page.totalLines > 200).map(page => ({ file: page.path, lines: page.totalLines, exact: page.totalLinesExact })) };
```

Await work whose completion matters; pending work ends with the script. Promise.allSettled keeps useful partial results, including failures. Return the fields needed for your next decision; without return, the last value-producing expression is used. Console output is also returned, so keep it brief.

Use sleep(ms) to wait within the script. Fetch is available when supplied by the host. Other external access goes through tools, not imports or direct filesystem access.
