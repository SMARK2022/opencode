@@ description
Run JavaScript in a confined Code Mode runtime to compose tool calls and HTTP requests.
Combine calls when their inputs are known or can be derived in code; return when the next step needs your judgment. Filter and aggregate intermediate results in the script, returning only the evidence needed for the next decision. Console logs also reach the model, so avoid printing entire intermediate results.
Use exact tool paths and signatures from the Code Mode catalog or global `search(...)`. Do not infer or normalize tool names; preserve bracket notation such as `tools.<namespace>["tool-name"](input)`. Tools shown outside that catalog are not available inside `{ code }`.
Await every call whose completion matters; pending calls are interrupted when execution ends. Run independent calls with `Promise.all`, or `Promise.allSettled` when partial results are useful. Keep dependent calls and conflicting writes sequential. Let errors surface unless you have a useful recovery or partial result to return; do not hide failed items in a success summary.
Prefer an explicit `return`; otherwise the final top-level expression becomes the result. Use each tool's documented result fields to judge success and completeness.
First discover: `return search({ query: "lookup orders" })`. If its signature describes `tools.orders.lookup({ id })` returning an order with `id` and `status`, then use those exact fields. Then compose: `const orders = await Promise.all(["a", "b"].map((id) => tools.orders.lookup({ id }))); return orders.map((order) => ({ id: order.id, status: order.status }));`. Replace the example path, inputs, and fields with what you discovered.
`fetch` is available for HTTP requests. Imports, direct filesystem access, and timers are unavailable: there is no `setTimeout` or sleep. All other external access goes through `tools`.
