02 设计思想调研

当前仓库为 opencode 的 SMARK 增强分支（dev-smark, v1.15.7），采用 client/server 架构。本地修改通过 [local-smark] 标记（190 处，76 文件）确保上游合并可恢复。

Effect-first 架构

Effect.gen/fn 组合，Schema-first 建模，InstanceState 按目录隔离，makeRuntime 共享 memoMap 去重 layer

Tool-first 交互

Tool.define() 自包含工具（参数 schema + execute + metadata），工具是模型与系统交互的唯一接口

多层权限系统

precheck 静态分类器 → auto-review LLM 审查 → manual ask。auto agent 4 级预审查是 LLM-cost 边界

Compaction 上下文管理

overflow 触发 → LLM anchored summary → Evidence Handoff → pruning → 4-turn tail retention

Provider-agnostic

多 provider 支持，provider-specific prompts 和 transforms，4-axis route 分解（Protocol/Endpoint/Auth/Framing）

[local-smark] 方向

LLM-cost-aware 权限路由、token/cost 可观测性、daemon 加固、Windows 一等支持、工具输出纪律

改造约束

[local-smark] 标记：所有改动标记确保合并可恢复  |  Effect-first：Effect.fn/InstanceState/Tool.define  |  向后兼容：Schema.optional 新增字段  |  渐进式：P0→P1→P2，每批 bun typecheck + bun test  |  不假设模型行为：harness 能 catch/redirect，不依赖"模型会做 X"

04 根因分析与改造方向

方向 1工具错误诊断不可操作[展开]
edit/apply_patch/notebook_edit/read-binary 的 error 只报告"期望什么"不报告"实际有什么"。read.ts:384 的 "Did you mean" 是唯一例外。
F-3F-16F-51F-54F-62

改造：在所有内容匹配工具的 error 中增加 actual content / available alternatives

方向 2上下文信息丢失且模型不知情[展开]
5+ 机制拥有信息但不传递给模型——auto-format、compaction、file watcher、LSP、typecheck errors
F-4F-14F-26F-38F-41F-55F-56F-58

改造：统一"信息前传"原则——harness 的 effect information 必须在 tool output 中对模型可见

方向 3循环检测层次不足[展开]
4 层循环检测各有盲区，合计覆盖率仅 5.1%。doom_loop 仅同消息精确匹配（10/816），无 semantic loop 检测（51% sessions 有）
F-5F-11F-42F-60

改造：扩展 doom_loop 到跨消息 sliding window + semantic 3-gram + typecheck caching + overlap suppression

方向 4Subagent 委托效率低下[展开]
65.2h 阻塞（100% foreground）、92% re-read parent files、12% 空结果、no background mode
F-10F-17F-30F-47F-61

改造：启用 background + 传递 inspected files + 空结果验证 + result 截断预算

方向 5Compaction 信息保留不足[展开]
summary 28% 保留率、Evidence Handflow 排除 search、pruning 不保护 read、splitTurn 跳 error、head/tail bias、memento 太小
F-14F-36F-55F-56F-57F-63F-64

改造：Evidence Handoff +Search History + pruning 保护 read + splitTurn 保留 error + 计数 + content-aware + memento min 4K

方向 6工具 Dedup/Registry 不完整[展开]
read stub 仅精确 range、skill 无 load dedup、outline per-read-range 不 per-file
F-1F-27F-33

改造：overlap>=80% suppress + skill load dedup + whole-file outline cache

方向 7工具输出缺乏可操作信息[展开]
bash timeout 不区分 hung/slow、truncation 总是 tail、grep/glob 无总数、glob 每文件 stat、webfetch 404 无建议
F-2F-7F-13F-18F-48F-31

改造：bash timeout 区分 + command-aware truncation + grep/glob count + glob stat opt-in + webfetch 建议

方向 8Harness Bug 修复[展开]
quotePattern .replaceAll on undefined（9 crashes）、offset=0 schema 不一致、retry 24.8 天上限
F-52F-53F-24

改造：guard + auto-correct + cap。零风险。

方向 9验证与步骤限制缺失[展开]
45% edit session 无验证、agent.steps ?? Infinity（111 sessions >100 steps）、typecheck re-run 无 caching
F-8F-21F-42

改造：默认 step ceiling 200 + session-end verification notice + typecheck caching

方向 10工具旁路与未覆盖路径[展开]
system prompt 不覆盖 bun -e/Select-String、无 git tool（5309 via bash）、WSL 5% encoding
F-6F-20F-44F-45F-46F-49F-59

改造：扩展 prompt + invalid substitute + WSL UTF-8 + 可选 git 结构化工具
