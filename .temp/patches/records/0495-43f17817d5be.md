## 关键落地细则（表格展开）

1. **smoke 脚本（14 hunks 全量）**：
   - win32 outer/child 分离：`OPENCODE_SMOKE_ROOT_REPORT` 唯一 IPC 路径，防递归双层 child；
   - root 在任何 PTY 创建前发布——scenario 早退仍有确定清理目标；
   - `scenarioError`/`cleanupError` 分槽：cleanup 失败不覆盖 first divergence；
   - `cleanupStep`/`terminatePty`/`terminatePID` 阶梯：单步失败继续释放其余 owner；
   - lock-owner PID 重读（replacement owner 场景）；"Ask anything" 输入就绪等待；
   - `requestTuiExit` 订阅先行 + win32 `exit\r`（原 `/exit\r`）；`waitForExit` 移除；
   - 应用方式：12 hunks 语义应用器精确命中 + hunk1/hunk-358 外科插入（目标块含 0489 新增注释的上下文漂移）。
2. **daemon spawn adapter（owner 迁移）**：源 `cmd/tui/daemon.ts` → 目标 `cmd/tui.ts`（目标 daemon 生命周期 owner）。
   - `DaemonProcess.spawn` 平台分支：Unix 直 Bun.spawn；win32 System32 绝对路径 powershell.exe + `-EncodedCommand`——脚本固定、动态路径仅经 `OPENCODE_DAEMON_EXECUTABLE/TARGET` env 传入，杜绝路径字符改变 PS 语法；
   - worker-PID 首行握手（可取消 timer + race）；`readWorkerPID` 首换行为协议边界，remainder 交 drain；`drainWrapperOutput` 持续消费防 pipe 背压（forward 仅控可见性）；
   - kill 先 worker 后 wrapper（无孤儿观察者）；`exited` 等待 pipe EOF；
   - 调用点 `await deps.spawn(...)`——`SpawnDaemon` 类型允许 Promise，`DiscoverDaemonDeps.spawn` 随 typeof 自动放宽，exited-compat 兼容 thenable。
3. **server-lock rename retry**：stale-reclaim 的 `rename(lockDir, stale-<token>)` 有界重试——25ms 探测节奏、1s deadline、仅 EPERM/EACCES/EBUSY（NT sharing 三类瞬时错误）可等待，其余立即保持 busy；所有 contender rename 到同一 tombstone，winner 占住后延迟 contender 只能失败。常量以字面量内联（源为命名常量），语义注释完整保留。
4. **core watcher 语义**：root 与 `.git` 两处 `Effect.forkScoped(subscribe)` → `yield* subscribe`（就绪等待，获取失败不再静默留在后台 fiber）；订阅获取失败 `Effect.logError` → `Effect.failCause` 上抛。外层 layer catch 见 R2 修复节：源同 hunk 将其 `Effect.void` 降级改为 `failCause`，本版已同步适配。
5. **daemon.test 四新用例**：
   - FileShare.Read 真实 NT 句柄（pwsh holder + stdin 释放协议）证明 rename 冲突码属白名单——形状断言而非次数断言；
   - retry marker 协议：maintenance-retry-worker 注入一次 EACCES，`rename-blocked`/`lease-owned` 发布 readiness，全程无 elapsed-time 断言；
   - space-target：1MB stdout 之后的 marker 证明 PID channel 持续 drain，且 `proc.pid` 为真实 worker 而非 wrapper PID；
   - launcher-exit：Project 内假 powershell.exe 证明 SystemRoot 绝对解析；inline launcher 经 `discoverOrSpawnDaemon` seam（源 Daemon.ensure 等价，返回 {url} 解构）；SSE 首事件 + lock PID 存活/ping/同 PID 三断言防 replacement daemon 伪装成功。
