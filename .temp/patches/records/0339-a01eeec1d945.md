## rev-parse 缓存机制详解
- **三态缓存 `excludeFilePath`**: `null` = 未计算（首次调用执行 git rev-parse），`undefined` = rev-parse 返回空字符串（路径不存在），`string` = 有效路径。`null` 和 `undefined` 的区分确保 rev-parse 只执行一次。
- **文件存在性仍每次检查**: `if (!(yield* exists(excludeFilePath))) return` 每次调用都执行。用户可能在工作期间创建/删除 `info/exclude` 文件，缓存路径但不能缓存存在性。
- **stat only untracked 原理**: `block = new Set(untracked.filter((item) => large.has(item)))`。large 只用于过滤 untracked，tracked 文件的 stat 结果被丢弃。改为 `untracked.map` 跳过 tracked 文件的无效 I/O。在大型仓库（如 chromium checkout）中 tracked 文件可能数万，跳过它们的 stat 显著减少 I/O。
- **concurrency unbounded 原理**: `fs.stat` 是无副作用的只读操作，不需要限流。unbounded 让所有 stat 并发执行，总耗时接近最慢的单个 stat 而非串行总和。
