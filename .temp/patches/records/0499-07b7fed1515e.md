## 调试史（失败修订闭环）

1. **FSUtil.existsSafe 静态调用 TypeError**：existsSafe 是 FSUtil.Service 实例方法而非命名空间静态 → layer 内 `const fs = yield* FSUtil.Service`，schedule/runAll 内经实例调用。修复后物化通过。
2. **ConfigInvalidError lsp.typescript.command**：目标 config schema 不接受 `disabled:false` 形态 → typescriptOnly 改为空配置（不覆盖 builtin 条目；此修正同时保住了 spyOn(Typescript, "spawn") 拦截——config 覆盖会替换 spawn 闭包使 spy 失效，症状为 "fake LSP process was not captured"）。
3. **lifecycle get 全 NotFound / status 空**双根因：① touchAs 带 "document" 走 bridge 失败分支提前 return（目标 touchFile 语义：无 bridge 的强触诊即失败，不得静默回落）→ warm 路径无参 touchFile 才走 getClients spawn；② lifecycleLayer 缺 SessionProjector.node → create 事件不投影、行不落库 → 补节点。
4. **deletion-vs-admission 断言 false**：源 active barrier 尾部含 `sessions.get(sessionA.id)` 存在性复查，适配初稿漏掉 → 补齐（resume 后 admission 必然 NotFound，不得安装不可见新 token）。
5. **Windows EBUSY rm(root)**：fake 进程 `cwd: root` 持锁致 tmpdir 清理确定性失败 → 将 0501 的 cwd: root→dir 修复前置并入 0499 端口（两 patch 同批；0501 的 cwd hunk 届时记为已满足，其余 spy finalizer/docs 仍由 0501 端口）。
6. **handoff 断言 sessionIDs 失踪**：waiting 判定误写为 `t === owner.token`；源语义是「任一已安装 token 在该 pending 上有 waiter」即当前 generation 接管 → 改回 `[...s.tokens.values()].some((token) => pending?.owners.has(token))`，旧 claimant 不回收、新 generation 原子接管同一 spawn。
7. **prompt 并发用例 ReferenceError lspDirectories**：mock 替换未落盘 → 补 InstanceState.directory tap push mock + import。
8. **attachWith refs TypeError**：attachWith(effect, refs) 非 dual 形态，pipe 直传丢参 → pipe 内显式 `(effect) => attachWith(effect, refs)`。
9. **sync 全文件 17 fail**：fixture 用了 RouteProvider 但未 import → 补 `../../../../src/context/route` 导入。
