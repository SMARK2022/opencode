## Summary

Patch 199 wires the auto-review pipeline (created by patches 196-198) into the
permission ask flow. When a permission rule evaluates to `auto`, the permission
service now runs `PermissionAuto.evaluate` which delegates to the deterministic
precheck, then the optional reviewer, before falling back to user approval.

The original patch targeted the old architecture (Bus, Layer.mergeAll, local
Action/Event/Error types). The adaptation remaps everything to the target's
LayerNode + AppNodeBuilderV1 + EventV2Bridge + PermissionV1 namespace.

## Key Adaptation Decisions

### Bus → EventV2Bridge

The original used `bus.publish(Event.ReviewCompleted, { ... })`. The target
uses `events.publish(Event.ReviewCompleted, { ... })` where `events` is the
`EventV2Bridge.Service` yielded in the layer. The Event definitions are created
with `define()` from the schema event module, not `BusEvent.define`.

### Layer.mergeAll → LayerNode.group + AppNodeBuilderV1

The original `defaultLayer` used `Layer.provide(Bus.layer)` plus
`Layer.provide(PermissionSessionCache.defaultLayer)` etc. The target declares
deps in `LayerNode.make({ ..., deps: [...] })` and the builder resolves them
automatically. No manual `Layer.provide` needed.

### Error classes in core, not opencode

`AutoDeniedError` lives in `packages/core/src/v1/permission.ts` alongside
`DeniedError`, `RejectedError`, etc. It is accessed as `PermissionV1.AutoDeniedError`
by consumers. The opencode permission index never re-exports error classes
directly — it only exports `Event = PermissionV1.Event`.

### Reviewer node deps

`PermissionReviewer.node` declares deps `[Config.node, Provider.node, Session.node]`
because the reviewer layer yields all three services. Session does NOT import
Permission in the target architecture (verified via grep), so there is no module
initialization cycle. The original patch's cycle concern was specific to the old
architecture where Session imported Permission.

### Permission.node deps

`Permission.node` now declares deps `[EventV2Bridge.node, PermissionSessionCache.node,
PermissionCircuitBreaker.node]`. The reviewer is NOT a dep because it is accessed
via `Effect.serviceOption(PermissionReviewer.Service)` — it is an optional
collaborator that may be absent in smaller runtimes and unit tests.

### Test env replacements

The `reviewedEnv` includes `PermissionReviewer.node` in the group (replaced with
a deterministic stub Layer) so that `Effect.serviceOption` returns `Some`. The
replacement mechanism in `LayerNode.compile` creates a new node with the stub
layer and empty deps, so Config/Provider/Session are not required. The
`PermissionCircuitBreaker.node` is also replaced with a stub for deterministic
non-denial counting. `PermissionSessionCache.node` uses its real layer (built
from Permission.node's deps).

### fromConfig filtering

The `approvals_reviewer` and `auto_review` keys in the permission config are
control fields for the auto pipeline, not permission names. `fromConfig` now
skips them explicitly. The `isAction` and `isPermissionObject` guards ensure
only valid permission actions are emitted as rules, preventing config metadata
from leaking into the evaluator.
