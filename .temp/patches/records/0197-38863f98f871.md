## Source vs Upstream vs Target Comparison

### Source (SMARK)
The source patch creates a deterministic, non-LLM permission precheck classifier that runs before the optional reviewer. It defines a three-way Decision type (allow/prompt/deny) and implements shell command analysis including wrapper unwrapping (bash -c, ssh, wsl, python -c), dangerous raw pattern scanning (rm -rf /, curl|sh, reverse shells), risky token detection (dd, mkfs, git reset --hard), sensitive path detection (.env, .ssh), and a banned auto-allow prefix list.

### Upstream (v1.17.20)
The upstream target has no deterministic permission precheck. All bash permission requests route directly to user approval (ask) or configured rules (allow/deny). There is no wrapper unwrapping, no dangerous pattern scanning, and no auto-allow prefix filtering. The shell tool's always-allow suggestion uses BashArity without any prefix safety check.

### Target Adaptation
The target architecture uses `PermissionV1` namespace instead of `Permission`. The shell tool's permission request type is `PermissionV1.Request` (not `Permission.Request`). The target's shell tool imports from `@/tool/bash-arity` and uses `BashArity` for command parsing. The adaptation:

## File-by-File Adaptation Details

### packages/opencode/src/permission/precheck.ts
- Decision type: three-way (allow/prompt/deny) with invariant that allow is only for plainly read-only commands
- UnwrapResult/RemoteResult: intentionally exclude `allow` — wrapper execution is never safe enough for deterministic approval
- SHELL_WRAPPERS: bash/sh/zsh/dash/fish/ksh — -c/-lc payloads inspected for deny patterns, still prompt
- POWERSHELL_WRAPPERS: pwsh/powershell — -EncodedCommand decoded (UTF-16LE base64), all wrapper usage prompt-only
- REMOTE_WRAPPERS: ssh/wsl — cross trust boundary, never auto-allow, payload extraction only for deny detection
- INTERPRETER_FLAGS: python -c, node -e, etc. — can synthesize shell/network calls, all non-critical eval forms route to prompt
- SENSITIVE_PATH_PATTERN: guardrail regex (not secret scanner), specific enough to avoid blocking ordinary files
- BANNED_AUTO_ALLOW_PREFIXES: 50+ prefixes too broad for always-allow, mirrors wrapper/interpreter/remote classifications
- evaluate(): only bash has coverage, other permissions prompt
- evaluateShell(): depth cap 4, raw scanning before token splitting, deny-wins aggregation
- dangerousRaw(): 12 regex patterns for rm -rf /, curl|sh, reverse shells, credential exfiltration, PowerShell Remove-Item, Python/Node file removal
- riskyTokens(): deny for dd/mkfs/shutdown (irreversible), prompt for git reset --hard/force push (reversible but needs confirmation)
- safeTokens(): read-only allowlist (pwd, ls, cat, grep, git status/diff/log), sensitive path guard, version-safe check
- gitSafe(): -C/-c global flags banned, status/diff/log/show allowed, remote -v and config --get/--list allowed
- normalizeCommandName(): strips path prefix and .exe/.cmd/.bat suffix, lowercases

### packages/opencode/src/tool/shell.ts

- Combined riskyGit + canAlwaysAllowPrefix guard prevents broad wrapper/interpreter prefixes from always-allow suggestions
