## Source intent
Two macOS CI flake fixes:
1. **tool.shell**: `cmd()` previously used the spawn `shell` option
   (`ChildProcess.make(command, [], { shell })`). On Bun/macOS, the
   `shell` option combined with `detached` has a bug where the stdout pipe is
   never established — `echo test` exits 0 with empty output. Fix: pass the
   shell path explicitly with `-c` args. `cmd.exe` keeps `/d /s /c` flags
   (disable AutoRun registry commands; canonical quote stripping). Explicit
   `-c` is behaviorally equivalent on all platforms.
2. **prompt-voice-recorder**: the drain-threshold coefficient
   `VOICE_RECORDER_DRAIN_BLOCKED_READ_MS = FRAME_INTERVAL * 0.75` (24ms) was too
   tight: macOS CI scheduler jitter can inflate a 4ms `busyWait` wall-clock
   measurement past 24ms, so `drainBufferedFrames` wrongly concluded the buffer
   was empty and dropped trailing queued frames. Raised to `0.9` → 28ms: 23ms
   headroom above queued read (~5ms), still below the 32ms live-frame period so
   live reads remain distinguishable. Jitter only inflates measurements, never
   shrinks them, so the 4ms gap cannot be closed by jitter.
