## Summary

This patch upgrades the auto permission-reviewer from `generateObject` to streaming
(`streamText` + `permission_review_decision` tool), and wires review status into
the TUI. The reviewer now persists real reasoning, text, and tool parts into the
hidden child session instead of a single opaque decision record. The TUI renders
an auto-review status line on shell tool cards, navigable to the reviewer child
session. Transcript projection excludes reviewer protocol request cells to prevent
them from being used as authorization evidence.

## Changes

### 1. `packages/opencode/src/permission/precheck.ts`
- **One-line regex fix**: Dropped `(?:^|[;&|]\s*)` anchor from the cautious
  sensitive-read regex in `cautiousRaw`. The anchor caused `if(Test-Path){
  Get-Content}` patterns to bypass cautious routing because `Get-Content` inside
  a conditional block doesn't follow a line start or `;&|` separator. Without
  the anchor, the `\b` word boundary alone is sufficient to match the read
  command while the SENSITIVE_PATH_ARGUMENT_PATTERN lookahead still constrains
  the target path.

### 2. `packages/opencode/src/permission/reviewer/transcript.ts`
- Added `permissionReviewerRequest` metadata exclusion to `renderPart`. Reviewer
  child-session request cells are visible for audit/navigation but are protocol
  records generated by opencode, not fresh user approval. Excluding them prevents
  future incremental reviews from treating protocol cells as authorization evidence.

### 3. `packages/opencode/src/session/processor.ts`
- **Complete branch**: Preserved `autoReview` metadata when tool completion
  replaces `metadata` with the tool's own result. Without this, the final shell
  card loses its link to the reviewer subagent after completion.
- **Error branch**: Preserved `autoReview` metadata on error terminalization.
  Denied/failed auto reviews terminalize the shell as an error, but the UI still
  needs the review result line and reviewer-session link attached while running.

### 4. `packages/opencode/src/permission/reviewer/service.ts` (major refactor)
- **`generateObject` → `streamText`**: Replaced structured object generation with
  streaming text + `permission_review_decision` tool. The reviewer model now
  produces visible reasoning and text before invoking the decision tool, mirroring
  a normal subagent run.
- **`runReviewerAgent`**: New function that persists an assistant message and
  delegates to `runReviewerStream` with session/message context. On stream error,
  updates the assistant message's `error` field for audit visibility.
- **`runReviewerStream`**: Core streaming function using `Effect.acquireUseRelease`
  with an `AbortController`. Processes `fullStream` events (reasoning, text,
  tool-input, tool-call) and persists each as a `MessageV2` part. Uses
  `ProviderTransform.message` middleware for message normalization, matching
  normal `SessionPrompt` requests. Falls closed if the model doesn't call
  `permission_review_decision`.
- **`markToolReviewing`/`markToolReviewed`/`markToolReviewFailed`**: Updated to
  accept reviewer session ID and assessment result. `updateToolAutoReview` merges
  existing metadata with progressive status patches (reviewing → allowed/denied).
- **`recordReviewerRequest`**: Changed from `synthetic: true` to
  `metadata: { permissionReviewerRequest: true }`. The request cell is now a
  visible audit-friendly message instead of a hidden synthetic one.
- **`renderReviewerPrompt`**: New helper that renders the system/user prompt as
  inspectable text for the child session user message.
- **`mergeOptions`**: Uses `remeda/mergeDeep` to merge provider options with
  model options for the reviewer stream.
- **`ToolJsonSchema.fromSchema(Assessment)`**: Converts the Effect Assessment
  schema to AI SDK `jsonSchema` for the `permission_review_decision` tool input.

### 5. `packages/tui/src/routes/session/index.tsx`
- **`PermissionReviewDecision`**: New component rendering the reviewer's
  structured decision (outcome/risk/auth/rationale) as a BlockTool cell.
- **`AutoReviewLine`**: New component showing a compact review status line
  (◌ reviewing, ✓ allowed, ! denied/failed/timed_out/fallback_user). Clickable
  to navigate to the reviewer child session.
- **`autoReviewMetadata`/`autoReviewLabel`/`autoReviewColor`**: Helper functions
  exported for unit testing.
- **Shell component**: Added `autoReview` memo, `navigate` from `useRoute()`,
  auto-review line in expanded view, auto-review label in collapsed preview, and
  `onClick` navigation on inline shell tool.
- **`toolDisplays`**: Added `permission_review_decision` to the set.
- **ToolPart switch**: Added match case for `permission_review_decision`.

### 6. Tests
- **`auto.test.ts`**: Added `if(Test-Path){Get-Content}` cautious routing test
  verifying the regex anchor fix.
- **`reviewer-prompt.test.ts`**: Added transcript-excludes-protocol-cells test
  verifying `permissionReviewerRequest` metadata exclusion.
- **`prompt.test.ts`**: Added integration test verifying reviewer streaming
  persists real reasoning and decision tool parts. Checks `tool_choice` is not
  "required", `permission_review_decision` tool is in the request, `max_tokens`
  is 10000, and child session has text/reasoning/tool parts with correct content.
- **`auto-review-render.test.ts`** (new): Unit tests for `autoReviewMetadata`,
  `autoReviewLabel`, and `toolDisplay("permission_review_decision")`.

## Adaptation Notes

- **TUI path**: Original patch modified `packages/opencode/src/cli/cmd/tui/routes/
  session/index.tsx`. Target has TUI at `packages/tui/src/routes/session/index.tsx`.
  The target TUI uses `toolDisplay()` for routing instead of direct `props.part.tool`
  checks, so `permission_review_decision` was added to the `toolDisplays` set.
- **Session API**: Target uses `session.*` methods (Session.Service wrapper) instead
  of `sessions.*` (Session.Service) and `MessageV2.*` directly. The `runReviewerStream`
  uses `session.updatePart`/`session.updateMessage` for persistence.
- **Types**: Target uses `@opencode-ai/core/v1/session` types (User, Assistant,
  TextPart, ReasoningPart, ToolPart) instead of `MessageV2.*`.
- **LayerNode**: Target uses `LayerNode` for layer composition instead of
  `Layer.provide`.
- **Schema conversion**: Target doesn't have `@/util/effect-zod/toJsonSchema`.
  Used `ToolJsonSchema.fromSchema(Assessment)` from `@/tool/json-schema` instead.
- **TUI test**: Original full-render test (`session-message-render.test.tsx`)
  doesn't exist in target. Created unit tests for exported helper functions
  instead, matching target's testing pattern.
