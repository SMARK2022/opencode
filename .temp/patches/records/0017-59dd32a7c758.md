### Key adaptation decisions
- **server.ts**: Added `SessionRequestUsage.node` to the `app` LayerNode group in `server.ts` (line ~247) so HTTP handlers can `yield* SessionRequestUsage.Service`. Without this, the handler group's context requirements don't match `RouteRequirements`, causing a type error at `server.ts:276`.
- **PromptInput schema**: Added `rootRequestID: Schema.optional(MessageID)` and `source: Schema.optional(Schema.String)` to V2 PromptInput, matching source intent. Removed all `as any` type assertions.
- **PromptPayload**: Added `"source"` and `"rootRequestID"` to `Struct.omit()` so API clients can't set these fields directly.
- **HTTP endpoints**: Declared 3 endpoints in `groups/session.ts` using `HttpApiEndpoint.get()` with proper Schema types. Implemented 3 handlers in `handlers/session.ts` using `Effect.fn()` (no `ctx: any` — framework infers context type). Registered handlers with `.handle()`.
- **CLI session info**: `SessionInfoCommand` uses `Effect.fn` + `Database.Service` + `sql` template literals for aggregation query. Uses `SessionID.make(args.sessionID as string)` to work around yargs type inference issue.
- **CLI --cost**: `costBySession` Map loaded from `RequestUsageTable` grouped by session_id. `formatSessionTable` extended with optional `costBySession` parameter.
- **stats.ts**: Exported `formatNumber` for reuse by session CLI. Added `ModelUsageEntry` type and `upsertModelUsage` helper for future integration.
