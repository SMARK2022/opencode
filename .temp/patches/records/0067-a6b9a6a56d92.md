### Precedence contract

同一具体文件的有序父 non-allow `[ask, deny]` 求值为 deny；附加 Session grant 后仍为 deny。同一文件的 `[deny, ask]` 求值为 ask；无 grant 时仍 ask，有 grant 时可以 allow。这一对反向顺序是拒绝简单 action 分区的直接证据，不能靠对授权通配串做一次匹配代替。

宽 Session grant `/tmp/allowed/*` 与窄父 deny `/tmp/allowed/private/*` 重叠时，public 文件仍 allow，private 文件 deny。父代理 allow 被原始 source 的过滤规则排除，所以 `[deny, allow]` 的继承 non-allow 策略仍是 deny；本项没有把后续完整 ceiling patch 的共享 allow 例外提前移植。父 Session 的 deny 继续参加主规则序列，默认 task/todowrite denies 与 experimental primary_tools 的现有重复过滤也不改变。

祖先限制是每组独立求值后全部非 deny 才允许使用 grant，不把不同祖先规则拼成一组后让后代 ask 覆盖祖先 deny。新生 child.permission 由 Session.create 持久化，Session.get 与 children 读回同一规则数据。基线 Session.CreateInput、Session Info 与规范 V1 Session 的 permission 均引用 PermissionV1.Ruleset；setPermission 通过 Session owner patch 复制整个规则对象数组，不对字段手工裁剪。新增条件因此必须在规范 schema 声明，而不是只给 TS 对象临时增加属性。
