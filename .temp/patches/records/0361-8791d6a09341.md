## Source intent
`runReviewerStream` consumes `streamText().fullStream` directly but has no
finish-step handler, so the reviewer assistant message keeps `tokens` at the
initial 0 and never writes a step-finish part. `tokenAccounting` therefore
computes input=0 and breakdown=null for reviewer sessions, making the subagent
footer and sidebar /context panel show wrong numbers. The fix mirrors the
main-pipeline finish-step handling in processor.ts: call `Session.getUsage` to
update `message.tokens`/`cost`, write a step-finish part carrying
`inputChars` + `inputBreakdown`, and immediately `updateMessage` to close the
`stepSF && !msgCompleted` timing window. The inputBreakdown is computed
per-component (system/instructions/skills/tools/messages) using the same
formula as prompt.ts, and under OAuth the system message is routed to the
instructions partition instead of the system partition.
