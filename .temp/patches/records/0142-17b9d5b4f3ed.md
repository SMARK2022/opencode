## Source intent (from original patch, not subject line)
Original `0142-17b9d5b4f3ed` restructures Read tool behavior:

1. **Default window**: description and runtime default move from **400 → 200** lines.
2. **Structured model-visible output**: `<file>`, `<content>`, optional `<outline>`, `<range>`, `<more>`, `<stub status=…>`, optional `<note type="overlap">` instead of plain numbered dump only.

7. **Visibility filters**: compacted tool parts and prior stubs (`meta.stub`) must not act as coverage sources for later stubs.
8. **Public description asset** `packages/opencode/src/tool/read.txt`: document 200 default, stub reuse, and range/more/outline targeting.

### Control flow at tip
1. `Tool.define({ description: DESCRIPTION })` loads `read.txt` (200 + stub/outline guidance).
2. Execute: permission → resolve path → stream/lines under Effect (upstream baseline).
3. Build `ReadRangeMeta` (canonicalPath, start/end, size, modifiedMs, stub flag).
4. `collectVisibleReads(messages, canonicalPath)` walks recent assistant tool parts reverse-order; skips non-completed, compacted, and `meta.stub`.
5. `findReadStub(visible, current)`: same size+mtime only; prefer exact start-end (`stub_same_range_visible`); else covering range (`stub_covered_range_visible` + coveredBy).
6. If stub: `renderReadStub` structured output; **no** full content body.
7. Else: `findOverlapNote` may attach short note; `renderReadOutput` emits structure + content (+ outline when large source at offset 1).
8. Outline via `readOutline(filepath, total, offset)` with `MAX_ENTRIES=32`, `MAX_CHARS=640`, `MAX_ITEM_CHARS=60` truncation to `...`, multi-language rules.
