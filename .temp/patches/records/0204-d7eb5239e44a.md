## 3. SMARK Intent
- User-visible behavior: `filterCompacted` now normalizes its input by sorting messages newest-to-oldest (`b.info.id.localeCompare(a.info.id)`) before the boundary walk. Callers may pass either a newest-first stream or a chronological array; both produce the same compacted prompt window.
- Protected invariant: the compaction summary assistant must be seen before its parent compaction user so the walk can stop and restore the retained tail. MessageID.ascending() is the persisted ordering invariant; relying on caller order could revive pre-summary history and inflate the next compaction request past the model limit.
- Normal path: `filterCompacted(msgs)` builds `ordered = Array.from(msgs).toSorted(...)`, iterates `ordered`, then slices the compaction/summary/tail/continue window as before.
- Boundary/error paths: unchanged — empty iterable, missing summary, errored assistant, and tail_start_id remap all behave as before; only the iteration source changed from `msgs` to `ordered`.
