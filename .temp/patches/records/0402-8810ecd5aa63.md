## Source intent
Follow-up refinement over 0401 that fixes three defects in the fresh LSP
chain:
1. TUI diagnostics rendering is too coarse: multiple errors are hard to tell
   apart, multi-line Pylance messages inflate the tool block height, long
   messages lack stable truncation, and a clean check result gives no visible
   confirmation. The fixes land in two TUI files — session-v2.tsx (legacy
   plugin) and routes/session/index.tsx — rewriting the Diagnostics component
   into a tri-state presenter:
   - new errors: header `LSP · N new errors · +M more` + up to 3 single-line
     rows with [line:col], message whitespace normalized to single spaces and
     truncated at 120 chars;
   - existing-only: muted `LSP checked · 0 new · N existing` (count, no
     detail);
   - fully clean: green `✓ LSP checked · no errors in this file`.
   State derives ONLY from `metadata.diagnosticSummary` — an absent summary
   never renders clean, so an unavailable LSP cannot be mistaken for success.
2. read/touch semantic split: `lsp.touchFile(input, diagnostics?)` on a bridge
   now returns immediately when `diagnostics` is undefined (read warm must not
   `showTextDocument` in VSCode); strong touch (edit/write/apply_patch/lsp
   tool) keeps the `/lsp/touch` bridge call.
3. clean-误报 prevention: `bridgeDiagnostics` state on the LSP State marks a
   bridge as "ok"/"failed" after each diagnostics round; `status()` reports
   the VSCode pseudo-client as connected ONLY when diagnostics did not fail;
   tool layers drop `diagnosticSummary` from metadata when `status()` returns
   empty, and emit a short confirm line (`checkedMessage`) when LSP is up and
   delta is empty — single-file copy vs `changed-files` copy for apply_patch.
