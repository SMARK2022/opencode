## Port decision summary

Six surgical improvements to the vscode-notebook tool harness, derived from a full forensics
pass over `opencode.db` (893 tool calls / 89 errors). The goal is a lower edit error rate:

1. **edit response after-source preview** — the edit summary now appends the first 10 lines of the
   post-edit cell source (capped at 4 KB) so the agent can copy an exact `oldCode` anchor for the
   next edit instead of reconstructing text from memory (43% of edit errors traced to oldCode
   drift).
2. **client global request queue removed** — `callBridge` no longer serializes every bridge HTTP
   request through a global Promise queue; the server-side `withFileLock` already serializes per
   filePath, and the old queue let one long `run` (up to 50 min) block all subsequent
   summary/source/edit/env calls across all notebooks.
3. **source auto-expands limit** — when `cellId` is given without an explicit `limit`, the cell
   window expands to the whole cell (max 1000 lines) so a paged read cannot straddle a page
   boundary and break the next edit's oldCode match.
4. **non-string array detection** — `edit` rejects `oldCode`/`newCode` arrays containing
   non-string items before any cell mutation, preventing `sourceProp` from silently returning
   `undefined` (misleading "newCode is required") or a silent full-cell replacement.
5. **configure selectKernel timeout** — the server races `notebook.selectKernel` against a 15 s
   timeout and reports `selection-requested` instead of blocking until the client's 120 s timeout
   aborts with no useful information.
6. **cell_not_found message generalized** — the error text no longer mentions "edit response"
   (the error is shared by edit/run/source/output) and now recommends `vscode_notebook_summary`
   to obtain the current cell map.

All six changes are ported with their accompanying tests (one new concurrency test in
`vscode-bridge.test.ts`, ten new tests in `vscode-notebook-tool-summary.test.ts`).
