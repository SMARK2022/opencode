## Port decision summary

The goal-set handler previously mapped every `GoalError` (too long / empty / bad budget / no
goal) to an empty `HttpApiError.BadRequest({})`, so the TUI could only show the generic "Failed
to update goal" and the user could not diagnose the rejection. The fix:

1. New `GoalApiError` wire error (mirrors `ApiNotFoundError`'s `Schema.ErrorClass` +
   `httpApiStatus` pattern) carrying the specific reason in `data.message`; `_tag` is
   `"GoalApiError"` to avoid clashing with the domain `GoalError` (`_tag="GoalError"`) in
   `catchTag`, while the wire `name` stays `"GoalError"` for client readability.
2. The `goalSet` handler's `catchTag("GoalError", …)` now fails with
   `new GoalApiError({ name: "GoalError", data: { message: error.message } })` instead of an
   empty BadRequest.
3. The TUI `setGoal` reads `body.data.message` from the NamedError-shaped response and falls
   back to the generic text when parsing fails or no message exists.
4. The TUI adds a 4000-char client-side precheck that skips status-only updates (Pause/Resume
   send `objective: undefined`), and `MAX_OBJECTIVE_CHARS` is exported from `session/goal.ts` so
   the client can reuse the single source of truth.
5. A new `test/server/httpapi-goal.test.ts` guards the wire shape: four rejection-reason cases
   (over-long / whitespace-empty / non-positive budget / status-only-with-no-goal) assert
   `{name:"GoalError", data:{message}}`, plus a happy-path regression guard and a 404
   not-found regression guard.

## Key adaptation (TUI import boundary)

The upstream TUI change imports `MAX_OBJECTIVE_CHARS` via `@/session/goal`. In this series the
TUI lives in `packages/tui`, which has NO `@/` path alias and does NOT depend on the `opencode`
package (only `@opencode-ai/core` / `@opencode-ai/sdk` / `@opencode-ai/plugin` / `@opencode-ai/ui`).
`@opencode-ai/core/session/goal` does not resolve (core has `goal.sql.ts`, not `goal.ts`).
Therefore the import is replaced by a LOCAL mirrored constant
`const MAX_OBJECTIVE_CHARS = 4000` in `dialog-goal.tsx`, with a comment documenting that it
mirrors the server-side `SessionGoal.MAX_OBJECTIVE_CHARS` (the server keeps the single source of
truth). The precheck behavior, the status-only skip, and the error-message extraction are all
preserved.
