"LSP 显示 disabled" gap and stops stale-diagnostic noise in edit feedback:
1. Default-enable LSP: `if (!cfg.lsp)` becomes `if (cfg.lsp === false)`; the

   upstream; the fork opts in deliberately (lazy spawn keeps startup cost ~0).

   to keep background LSP warm-up defects from escaping the read scope.

   `lsp/diagnostic.ts` replicate Copilot's "new errors introduced by a file
   edit"; MAX_PER_FILE 20→5; baseline captured BEFORE touch so pre-existing
   errors never re-render after an edit (issue #9102).
4. VSCode Bridge LSP backend: new `sdks/vscode/src/lsp.ts` (touch/diagnostics/
   hover/definition/references/symbols via VSCode APIs, `showTextDocument` only
   for strong touch), registered in `bridge.ts` route table + READONLY_ROUTES,
   `lsp: true` capability in the registry manifest; opencode `lsp.ts` resolves
   the bridge first (`resolveLspBridge` + `callLspBridge` + bridge->internal
   diagnostic map) and falls back to built-in servers.
5. TUI DiagnosticsDisplay enhancement wiring: edit/write/apply_patch metadata
   carries `diagnostics` (delta array) + `diagnosticSummary`; apply_patch gains
   diagnostic rendering it previously lacked.
