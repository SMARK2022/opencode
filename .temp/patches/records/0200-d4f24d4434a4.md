## 3. SMARK Intent
- User-visible behavior: Introduces an isolated hidden reviewer agent that can only produce structured allow/deny decisions. Normal agents and user config cannot access, unhide, or spoof the reviewer.
- Protected invariant: `permission-reviewer` must remain hidden, deny-all except the decision tool, and unreachable by normal task routing. Reserved-name set prevents config override. Object-reference comparison in `tools()` prevents config-spoofed agents from minting review metadata.
- Normal path: Reviewer is registered as a hidden subagent; decision tool is registered but not publicly listed; `tools()` returns it only when `input.agent === internalReviewer` by reference.
- Boundary and error paths: TaskTool rejects `permission-reviewer` and any `hidden` agent with `Agent type is not available` before reaching `bypassAgentCheck`. Config loop skips reserved keys entirely. `value.name` reassignment is guarded.
- Concurrency/exit/cleanup/security paths: No concurrency changes. Security boundary is the primary concern: the reviewer cannot execute tools (deny-all), cannot be discovered (hidden + filtered), cannot be called by normal task routing (rejection in TaskTool), and cannot be spoofed (object-reference gate in `tools()`).
