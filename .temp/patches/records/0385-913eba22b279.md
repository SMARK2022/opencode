## Source intent

Windows CI default shell is pwsh (PowerShell 7). Its .NET runtime cold start plus
first `echo` output can take 600ms+ on CI hosts, while the tests used a 500ms
timeout (500ms implementation timeout + 100ms buffer). The timeout therefore fired
BEFORE the echo output reached the output pipe, so `result.output` did not contain
"started" and the assertion failed intermittently.

The fix is test-only: introduce a platform-aware constant
`const timeoutMs = process.platform === "win32" ? 3000 : 500` and use it in three
`echo + sleep + short-timeout` tests:
1. "Timeout test" (abort section): `timeout: 500` → `timeout: timeoutMs`, and the
   `<opencode_notice ... timeout_ms="500">` assertion becomes a template literal
   with `${timeoutMs}` so the asserted value always matches the actual timeout.
2. "uses RuntimeFlags bashDefaultTimeoutMs when timeout is omitted":
   `bashDefaultTimeoutMs: 500` → `timeoutMs` and the `timeout_ms="500"` assertion
   becomes the same template literal, keeping notice vs layer value consistent.
3. Truncation-section "Timeout with output test": `timeout: 500` → `timeoutMs`.

No implementation code changes; the timeout race logic, kill flow, and
block-buffering diagnostic are untouched.
