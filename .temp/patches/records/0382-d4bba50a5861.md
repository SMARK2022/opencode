## Source intent

The VSIX packaging code already lived in `sdks/vscode/script/vsix.ts`, but CI was
never wired to it — every release required a manual build. The patch adds a
dedicated `.github/workflows/build-vsix.yml`:

1. Trigger: `workflow_dispatch` (with an optional `version` override input) plus
   `push` on `dev-smark` filtered to `sdks/vscode/**` and the workflow file itself.
2. Version resolution priority: workflow input > `sdks/vscode/package.json`
   `version` field, fail-closed on empty or literal `"undefined"` (node -p prints
   "undefined" with exit 0 when the field is missing). Version is NOT derived from
   the workflow-triggering tag — this workflow never depends on tag pushes.
3. Build: `bun install` inside `sdks/vscode` (it has its own `bun.lock` and is not
   in the root workspace), then `bun run package`, then
   `bun x @vscode/vsce@^3 package "$VERSION"` with `--no-git-tag-version
   --no-update-package-json --no-dependencies --skip-license`, output to
   `dist/opencode-vscode-$VERSION.vsix`.
4. Release: an `actions/upload-artifact@v4` step (fail on missing files) plus a
   GitHub Release upload step that mirrors `build-opencode.yml`'s pattern — the
   workflow itself creates the `vscode-v$VERSION` tag with `gh release create
   --target $GITHUB_SHA --generate-notes`, and re-runs for the same version go
   through `gh release upload --clobber`.
5. Root `package.json` gains the `vsix` convenience script
   `bun run --cwd sdks/vscode vsix`.

Rationale in the source commit: the `vscode-v*` tag prefix isolates the extension
releases from the CLI `v*` releases so the CLI release message body and history are
unaffected.
