## Source intent
The original commit fixes two related harness issues in `src/session/prompt.ts`:
1. The `nearOverflowNotified` flag was only reset after compaction. When the model switches (e.g. 128K model → 1M model) without compaction, the flag stayed `true` and later growth past the new model's threshold would never re-prompt. Symmetric bug in reverse direction (big model → small model: flag stays true even at 100%).
2. The threshold was raised 80% → 85% to avoid prompting too early.

The fix restructures the near-overflow check into a two-way guard: inject the ephemeral prompt when estimatedInput >= 85% of usable tokens (once), and reset the flag when usage drops below the threshold (e.g. after a model switch to a larger-context model) or when the model has no upper bound (`usableTokens === 0`, threshold 0 → never prompt, else branch still resets). The compacted-reset at the compaction path is preserved (double coverage).
