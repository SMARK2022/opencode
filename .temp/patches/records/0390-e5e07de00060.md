   pipe 顺序。旧代码超时在外层：`timeoutOrElse` 以 interruption 杀死 fiber →
   `SessionRetry.retry` 看到 cancellation 不重试 → `orElse` 产生新的
   `ReviewerTimedOut` failure 位于 `catchIf` 之外 → 零重试直达
   `handleReviewerFailure`。新实现为递归 `reviewerRetry(attemptNum,
   currentMessages, hideOnProtocolError)`：per-attempt 超时在 catchIf 内层，

   `MAX_REVIEWER_ATTEMPTS = 3` 次；协议错误重试附加 PROTOCOL_RETRY_USER_ITEM
   nudge，超时重试保持原 prompt。`timeout_ms` 语义由 total 变为 per-attempt，
   config 描述同步更新。
2. **Change 2/3**：两个 `Effect.onInterrupt`——runReviewerAgent 内在超时中断时
   给子会话 assistant 消息写终态（error=AbortError + time.completed），复用
   prompt.ts finalizeInterruptedAssistant 模式；review 外层在外部取消时
   `markToolReviewFailed(input, "aborted", ...)`，作为
   processor.interruptedToolMetadata 的补充。
3. **Change 4**：updateToolAutoReview 守卫——`patch.status === "aborted"` 且
   current.status 非 "reviewing" 时 return，防止 onInterrupt 延迟覆盖
   timed_out/failed/fallback_user/allowed/denied 终态；markToolReviewFailed 与
   patch 的 status 联合类型加 "aborted"。
4. **Change 5**：errorMessage 增强——Error 对象带 responseBody/statusCode 时
   `${message} (${statusCode}): ${responseBody.slice(0,300)}`；无 message 的
   非 Error 对象用 JSON.stringify（?? String 兜底 undefined，try-catch 防循环
   引用）。
5. **Change 6**：assessmentFromJsonText 宽容提取——先整体解析，失败后
   `extractFirstJsonObject`（括号深度扫描 + 字符串/转义处理）提取第一个完整
   JSON 对象再解析；Schema 校验与 invalidReviewContract 守卫不变。
6. **Change 7**：message-v2.ts transportError 增加 `!code &&
   message.includes("socket connection was closed")` 兜底（undici socket close
   经 AI SDK 包装后可能丢失 code，TRANSIENT_TRANSPORT_CODES 匹配不到）。
7. **Change 9-11**：协议重试失败测试 2→3 次断言；新增超时重试测试
   （timeout_ms=500 + llm.hang → 重试成功，中断 assistant 有终态）；新增
   prose-prefixed JSON 提取测试（→ json_fallback 决策）。
