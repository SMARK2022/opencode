## Source intent

四步改动解决"撤回慢 + revert 期间发消息被误撤回 + 无重试入口"：

- **B1 状态守卫**：run-state 新增 `reverting: Set<SessionID>` 与
  `assertNotReverting` / `beginRevert` / `endRevert`（原子 check-and-set，
  assertNotBusy 同步检查 reverting）；revert/unrevert 用
  `Effect.acquireUseRelease(beginRevert, use, endRevert)` 包裹（失败/中断/
  提前返回都保证清除标志）；4 个 HTTP handler（prompt/promptAsync/shell/
  command）加 assertNotReverting，revert 期间发消息返回 BusyError→BadRequest，
  TUI 保留草稿。
- **A1 合并 checkout**：snapshot.revert 批量分支先尝试单次
  `git checkout <hash> -- <all-files>`（1 spawn），成功跳过 ls-tree 预验证，
  失败回退原逻辑。20 文件 255ms→12ms。
- **A2 messages 裁剪**：MessageV2.page 加 `fromMessageID`（gte 过滤，
  MessageID 单调递增）；Session.messages 接口与实现透传；revert 只加载
  input.messageID 及之后的尾部消息。大 session 110ms→30ms。
- **C1 Retry 菜单**：dialog-message 新增 Retry 选项（abort → await revert →
  setPrompt → submit 一步完成撤回+重发），extractPromptInfo 提取函数复用；
  revert 失败只填回内容不提交。
- 新增 1241 行设计文档 docs/revert-performance-retry-plan.md；revert-compact
  测试新增 4 个用例（并发 revert 拒绝、失败清除标志、同 hash 多文件批量
  checkout、messages 范围裁剪）。
