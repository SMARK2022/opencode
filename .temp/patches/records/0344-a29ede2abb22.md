## Source intent

### Hunk 1 — `@@ -2410,10 +2410,12 @@` (index.tsx, BlockTool comment update)
The upstream commit (a29ede2ab) refines the hiding strategy introduced by 0343 (a1a2952e2c). The 0343 approach used `maxHeight=0 + overflow=hidden` to hide preview/body when collapsed/expanded. However, OpenTUI's `updateFromLayout` applies `Math.max(layout.height, 1)` which forces a height of 0 to 1, leaking the first line of the hidden region. For shell tool blocks where both preview and body contain `$ command`, this causes the command to appear twice on screen.

The fix: replace `maxHeight=0 + overflow=hidden` with `visible={false}` (display:none), which removes the node from the layout tree entirely while keeping it mounted (preserving 0343's fix for collapse→expand→collapse blank content). No-preview blocks (TodoWrite/Question) still use `maxHeight=previewLines` clipping.

### Hunk 2 — `@@ -2462,23 +2464,23 @@` (index.tsx, BlockTool JSX prop changes)
Three concrete prop changes:
- **Preview box**: `maxHeight={collapsed() ? undefined : 0}` + `overflow={collapsed() ? undefined : "hidden"}` → `visible={collapsed()}`
- **Body box**: `maxHeight={collapsed() ? (hasPreview() ? 0 : previewLines()) : undefined}` + `overflow={collapsed() ? "hidden" : undefined}` → `visible={!collapsed() || !hasPreview()}` + `maxHeight={!hasPreview() && collapsed() ? previewLines() : undefined}` + `overflow={!hasPreview() && collapsed() ? "hidden" : undefined}`

The body box now has THREE props: `visible` controls display for preview-having blocks, while `maxHeight`/`overflow` only apply to no-preview blocks (the TodoWrite/Question fallback path).
