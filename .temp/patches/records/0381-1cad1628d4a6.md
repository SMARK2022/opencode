## Source intent

Source upgrade is a full dependency train: `@opentui/core` / `@opentui/keymap` /
`@opentui/solid` 0.2.11 → 0.3.4 and `opentui-spinner` 0.0.6 → 0.0.7 (peer `^0.3.4`,
chosen over 0.4.3 because spinner 0.0.6/0.0.7 segfault against 0.4.3), plus three
non-dependency changes:

1. `bun.lock` / root `package.json` catalog bump 0.2.11→0.3.4, spinner 0.0.6→0.0.7,
   `packages/plugin/package.json` peer ranges `>=0.2.11` → `>=0.3.4`.
2. `script/upgrade-opentui.ts`: Windows path-separator bug — `file.split("/")` cannot
   match `\` separators returned by `Bun.Glob` on Windows, which caused
   `node_modules/**/package.json` to be wrongly rewritten by the upgrade script.
   Fixed to `split(/[\\/]/)`.
3. `packages/opencode/test/cli/cmd/tui/session-layout.test.ts`: new CJK behavior
   tests. Root cause being locked: when CJK fullwidth chars (2 cells each) exactly
   fill a visual row (even width), native `getRealCharBytes` does not append a row
   break `\n`, so `captureCharFrame()` collapses all text into the first line. The
   fix landed in OpenTUI 0.3.4; the tests lock `TextRenderable` and
   `TextareaRenderable` wrapping at the exact boundary (12 CJK chars per 24-cell
   row), reject U+FFFD replacement chars, and add a `SpinnerRenderable` peer-compat
   smoke (mount + render through `createTestRenderer`).
