## Source intent

修复 0393 C1 Retry 引入的运行时崩溃：点击消息 → `dialog.replace(() =>
<DialogMessage />)` → DialogMessage 内 `usePromptRef()` 抛
"PromptRef context must be used within a context provider"。

**根因（组件树层级）**：DialogProvider 在 PromptRefProvider **之上**
（app.tsx 258 vs 262）。`dialog.replace()` 的渲染区
（`{value.stack.at(-1)!.element}`）是 `{props.children}`（含 App → 各
Provider）的**兄弟节点**，SolidJS context 只向下传递，因此 dialog 渲染区
拿不到 PromptRefProvider 的 context。useSync/useSDK/useRoute 正常是因为它们
的 provider 都在 DialogProvider 之上。

**修复**：DialogMessage 移除 usePromptRef import 与调用，新增可选
`submit?: () => void` prop；由 session/index.tsx（PromptRefProvider 内，
`promptRef.current?.submit()` 可用）在调用点注入，经 DialogTimeline 透传；
Retry onSelect 的 `promptRef.current?.submit()` 改为 `props.submit?.()`。
三处调用（DialogTimeline 的 replace 内 + 消息点击的 replace 内）全覆盖，
同时补齐 DialogTimeline 的 submit prop 声明。行为：submit 未注入时
optional chaining 静默降级不提交（不崩溃）。

新增 264 行方案文档 docs/promptref-context-fix-plan.md（组件树证据 +
方案对比 + 边界路径）。
