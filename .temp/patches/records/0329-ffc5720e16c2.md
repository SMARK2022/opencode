## 原子替换详细分析
- 旧方式：cp $src $dst + chmod 755 $dst（原地覆盖）
- 新方式：mktemp 临时文件 → cp $src $tmp → chmod 755 $tmp → mv -f $tmp $dst
- macOS 问题：运行中的 daemon 映射旧 inode，cp 覆盖导致内核对被覆盖 Mach-O 做 cs_invalid_page 校验失败 → SIGKILL
- 原子替换：mv 是同文件系统纯 rename，旧 inode 保持有效，daemon 不受影响
- Windows 退回：运行中的 .exe 被独占锁，rename 失败 → rm $tmp + cp $src $dst + chmod（同旧行为）
- 清理：rm -f ${dst}.install.* 清理上一轮崩溃残留的临时文件
