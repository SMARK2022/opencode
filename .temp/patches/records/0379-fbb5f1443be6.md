## Port decision summary

User authorization instructions often sit at the END of long messages (e.g. a TDD instruction
block followed by "## 创建 commit"), but the reviewer transcript truncation kept only the first
1000 chars of each entry, so the reviewer could not see the trailing authorization evidence and
fail-closed wrongly rejected legitimate operations. The fix:

1. `truncateWithFlag` gains a `preserveTail` parameter: when truncating a USER message, keep the
   head 60% (context) + tail 40% (trailing authorization) with the truncation marker in the
   middle; the marker's `chars` count still equals exactly the omitted characters. Non-user
   messages and tool output keep the original head-only truncation (no scope creep).
2. The user-message entry budget rises from 1000 to 2000 chars to cover common long
   instruction + authorization scenarios; worst case 40 × 2000 = 80k chars is safe for any
   ≥128k-context reviewer model.

Both production and test changes are ported verbatim.
