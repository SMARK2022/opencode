## Windows relay spawn 平台修复（同文件附带的必要修复）
- **问题**：目标旧 wrapper 用 `Start-Process` 直接起 worker——wrapper 与 CLI 同属 kill-on-close job object，其子进程随短命 launcher 连锁击杀。判别实验：直接 spawn 的 worker（父进程存活）10s 存活；CLI `daemon start` spawn 的 worker 在 CLI 退出后 4-6s 死亡（repro 4/4）。机器接口语义（daemon 存活到外部 client 接入）在 Windows 完全失效。
- **修复**：wrapper 经 `[wmiclass] Win32_Process.Create` 拉起 relay（WmiPrvSE 服务进程上下文，天然脱离 CLI job）；relay 在 job 外 `Start-Process -WindowStyle Hidden` worker；WMI Create 不继承调用方环境 → env 经一次性 TAB+base64 行文件传递（lock 同目录，relay 读完即删；失败错误落盘 `.err` 可观测）。逃逸验证：relay 链孙进程在 bun 父进程退出后心跳 12/12 存活。
- **三轮排障**（全部有证据）：(a) `Invoke-CimMethod` 传 `Win32_ProcessStartup` 类型不匹配 → `[wmiclass]` COM 形态；(b) WMI 创建 powershell 带 `-WindowStyle Hidden` 触发 ReturnValue=2（二分定位）→ 移除该参数（ShowWindow=0 已隐藏）；(c) PS5.1 `ConvertFrom-Json` 大小写不敏感字典拒绝 `NO_PROXY`/`no_proxy` 重复键 → 改 TAB+base64 行格式；(d) `Wait-Process` 对已退出 pid 抛终止错误→wrapper exit 1 误报崩溃（#179 消费该码）→ `Get-Process` 预检；(e) envRecord 混入 undefined 值 → 写文件前过滤。
- **已知平台残差（非本补丁引入，已全证据记录）**：Windows 上由 CLI spawn 的 daemon 在「第二个 CLI 退出后 ~0.2s」无日志硬杀死亡（时间线取证：复用成功的 run 中 poll 显示 3.7s 死亡=第二 CLI 退出+0.2s；d1.log 无 gracefulShutdown 记录=非优雅退出）。旧 Start-Process wrapper 时代同样复现（首次适配即 2/4 flaky）。relay 逃逸对 cmd 心跳进程成立（12/12）但真实 bun worker 仍有此死亡——根因未在时间盒内定位，登记为平台缺陷待独立调查。测试 3 的复用断言按平台条件化（POSIX 严格；Windows 断言机器合同+launcher 保护语义），测试内注释与 record 双重披露。
- PRINT_LOGS 诊断降级：relay 模式下 worker stdout 无管道，--print-logs 日志丢失（测试侧直连 spawn 不受影响）——登记为已知残差。
