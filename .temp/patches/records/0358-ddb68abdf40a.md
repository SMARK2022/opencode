## Source intent
Two timeout defaults in the provider layer:
1. `DEFAULT_TIMEOUT_MS` relaxed 300_000 → 600_000 (5→10 minutes). The absolute
   per-request deadline (hard cap from fetch start, even while chunks stream)
   previously caused a retry loop: 5-minute timeout → `message-v2 transportError`
   classifies the AbortSignal.timeout as retryable → timeout again. 10 minutes
   lets ≤10-minute generations finish in one attempt.
2. `chunkTimeout` gains a default when unconfigured: `DEFAULT_CHUNK_TIMEOUT_MS =
   180_000` (3 minutes). Before, unconfigured chunkTimeout meant wrapSSE was
   disabled entirely (no idle protection on SSE responses). Now every SSE
   response gets the deadline; wrapSSE only aborts when NO bytes (heartbeat/
   comment bytes included) arrive for 3 minutes, so live streams are untouched.
   Explicit values still win. `chunkAbortCtl` is now created unconditionally and
   the old skip branch removed — wrapSSE's internal guards pass through
   non-SSE/empty-body responses unchanged.
