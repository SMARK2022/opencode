## 2. Upstream design
Claude Code provider wrapper (`packages/opencode/src/provider/claudecode.ts`) finalizes request bodies and may rewrite `cch=00000` via `patchCch` (xxHash of body). That makes the earliest system prefix change every turn, defeating stable-prefix caching.

`SystemPrompt.environment` in `packages/opencode/src/session/system.ts` assembles prompt parts. If volatile env/model identity is placed before static tool guidance, the prefix hash churns with cwd/date/git/shell.

## 3. SMARK design
1. Stop calling `patchCch` on the finalize path so `cch` stays the placeholder.
2. Move environment/model block to the end of `environment()` parts so static tool usage + guidance stay prefix-stable.

## 10. Call chain
1. Provider finalizes Claude Code request body → previously `patchCch` rewrote `cch` from body hash.
2. System prompt assembly builds an ordered list of parts; earliest static parts become the cacheable prefix.
3. Volatile env (cwd/date/git/shell/model) must not sit in that prefix or every turn busts cache.
4. After this patch: `cch` stays placeholder; env/model part is last in `environment()`.

## 11. Why env-at-end is stronger than "after toolUsage" only
V2 can have multiple static guidance segments after toolUsage. Moving the entire model+env joined part to the absolute end of the parts list maximizes the stable prefix under V2's real layout, which is a strict improvement over only swapping with toolUsage when more static parts exist.
