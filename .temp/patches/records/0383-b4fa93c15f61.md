## Source intent

The VSIX workflow created in 0382 uploads releases via `gh release create` without
status flags, so the first `vscode-v*` release becomes the repository's "latest"
release. Two concrete breakages follow:

1. The CLI install script (`install`) is downloaded through
   `releases/latest/download/install` — once a VSIX release takes the latest slot,
   that URL 404s because the release has no `install` asset.
2. Consumers that parse the latest release's `tag_name` for the CLI version would
   see `vscode-v1.17.x` and mis-parse it as the VSCode extension version instead of
   the CLI version.

Fix: add `--prerelease` to the `gh release create` invocation, plus a 4-line CJK
rationale comment spelling out both failure modes.
