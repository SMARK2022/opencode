## Source intent
Previously, connecting or disconnecting a provider from the TUI/Web app made
the server call `disposeAllInstances`, destroying every instance and forcing
other running sessions (including sessions on other providers/models) to be
cancelled by the `SessionRunState` finalizer. The fix replaces that with
`refreshProviderCaches` in the three server-side handlers
(`authSet`/`authRemove`/OAuth callback): it only refreshes the
`Provider.Service` cache via `ScopedCache.invalidateAll` (never touching
`SessionRunState`), then emits `global.disposed` so clients refresh their UI.
Running sessions keep using the old key to finish; the next new message
lazily rebuilds the cache and picks up the new key. The `configUpdate` path
keeps the old behavior (known limitation).

## Target-adaptation decisions
1. **App SDK naming**: the target app uses `serverSDK().client.global.dispose()`
   (not `globalSDK.client...`); only the dispose call is removed, the
   surrounding code is untouched.
2. **TUI sync.tsx handler shape**: the target already diverged from the source
   (uses `(event.properties as { reason?: string }).reason !== "daemon-stop"`
   + `void exit("opencode daemon stopped.")` from batch #273, not
   `daemonStopReason`/`DisposedReason.DaemonStop`). The semantic change is
   preserved: daemon-stop → exit; any other reason → `bootstrap()`. The
   `refreshProviderCaches` emission uses empty `properties` (non-DaemonStop),
   so the else-branch is what fires after auth changes.
3. **`log.warn` → `Effect.logWarning`**: the target's global-lifecycle.ts has
   no `* as Log` import; it already uses `Effect.logWarning("global disposal
   failed", { cause })`. The refresh failure branch uses the same idiom.
4. **`ScopedCache.invalidateAll(state.cache)`**: the target's provider state is
   an `InstanceState` whose `.cache` is a `ScopedCache` keyed by directory;
   `ScopedCache` is added to the effect import and `invalidateAll` invalidates
   every directory entry — matching the source's "all directories" intent.
5. **Tests adapted to `it.instance` style**: the target test file uses
   `testEffect(LayerNode.compile(...))` + `it.instance(...)` with `set`/`remove`
   Env helpers and `Provider.use.*` accessors, not the source's
   `withTestInstance`/`run(ctx, ...)`. The two tests are rewritten in that
   style; `Provider.use.invalidateAll()` is generated by `serviceUse` from the
   new Interface member. Model ID uses the target's `claude-sonnet-4-6`

## Risks / notes
- The `configUpdate` path intentionally keeps the old dispose behavior (source
  documents this as a known limitation); this patch does not touch it.
- `refreshProviderCaches` is fire-and-forget safe: `invalidateAll` failures are
  logged and swallowed because auth is already persisted to disk and the next
  access rebuilds lazily.
- The sync.tsx change makes non-daemon-stop `global.disposed` trigger
  `bootstrap()`; the `server.instance.disposed` handler still guards on
  `daemonStopSeen`, so no double-exit occurs.
- Typecheck of the change is covered by the batch-end `--typecheck 365`.
