## 补充说明（审计 N-01 收尾）
### instructions 提升的边界语义
- reviewerInstructions 只提取 role==="system" 消息的 content 拼接（flatMap），transcript/precheck reason/planned action 全部留在 user message——不可信证据绝不提升到 Codex 高优先级 instructions。
- reviewerMessages 在 instructions 模式过滤 system 消息，避免同一指令在 messages 与 instructions 双重注入；非 OAuth 路径 reviewerMessages === messages（恒等，wire 形状不变）。
- options = { ...baseOptions, instructions } 仅在 reviewerInstructions 存在时展开——baseOptions 保持 mergeOptions 原语义，普通 API key 请求无任何字段变化。
### OAuth 判定的双重条件
- isOpenaiOauthProvider(providerInfo.id, buildBaseProviderMap(cfg.provider ?? {}))：provider id 必须等于 openai 或 config 中 extends:openai 的别名（alias.ts L19-42 签名兼容）。
- authInfo?.type === "oauth"：凭据必须为 OAuth 类型（Auth.Info Schema.Union 的 Oauth 分支含 refresh/access/expires）。
- 两者缺一不启用 Codex 模式——customOauth 测试用例专门防止条件放宽回归。
### 目标 Auth 层差异
- 目标 auth/index.ts 无 defaultLayer，只有 node（LayerNode.make, deps: [FSUtil.node]）——defaultLayer 用 Layer.provide(LayerNode.compile(Auth.node)) 与既有 Config/Provider node compile 模式一致；reviewer node deps 补 Auth.node 是编译必需（layer yield 4 service），非 API 扩大。
- app-runtime.ts:83 消费 PermissionReviewer.node 自动获得 Auth 依赖，生产 wiring 完整。
### 测试适配的三种目标差异
- ModelID/ProviderID（source 的 provider/schema）目标不存在 → ModelV2.ID/ProviderV2.ID（@opencode-ai/core/model、@opencode-ai/core/provider，fake/provider.ts 同款用法）。
- Config.Info 未导出（config.ts type Info 非 export）→ config() 去显式类型注解，靠 TestConfig.layer 的 overrides 类型推断。
- approvals_reviewer: "auto_review" → as const（Schema.Literals("user"|"auto_review") 字面量类型，string 宽类型不可赋值）。
