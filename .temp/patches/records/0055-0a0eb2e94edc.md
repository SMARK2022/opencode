## 2. Upstream design (target before this patch)
Windows ShellTool (`packages/opencode/src/tool/shell.ts`) spawns PowerShell with `-Command` and plain command text. Child stdout is decoded as UTF-8 via `Stream.decodeText`. On Chinese Windows, PowerShell often emits GBK/OEM for cmdlet output, so UTF-8 decode yields U+FFFD. Upstream also set broad `JAVA_TOOL_OPTIONS` / `RUBYOPT` UTF-8 knobs on win32, which create side-effect noise without fixing PS Console encoding.

## 3. SMARK source design
Force the **producer** (PowerShell) to emit UTF-8 rather than invent a GBK decoder:
1. `psUtf8(command)` prepends Console I/O UTF-8 (`UTF8Encoding($false)` no BOM), sets `$OutputEncoding` from Console, runs user command, passthrough `$LASTEXITCODE` only when non-null.
2. `psEncoded` UTF-16LE→base64 for `-EncodedCommand` so non-ASCII CLI text is not mangled by `-Command` parsing.
3. `cmd()` on win32+PS: `-EncodedCommand` + encoded wrapper instead of `-Command`.
4. Drop JAVA/RUBY env overrides; keep Python-targeted UTF-8 vars.
5. Windows-only live test: Chinese `Write-Output` must appear and must not contain `\uFFFD`.

## 4. Target adaptation (this current)
